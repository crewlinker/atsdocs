The Sterndesk API uses Connect RPC over HTTP/JSON. This guide explains the common request format and special workflows you should understand before working with individual operations.

For complete request and response schemas, see the **API Reference**.

## Calling an operation

Sterndesk API operations are sent as `POST` requests to paths under `/rpc/`.

Authenticate each request using your personal API key:

```text
Authorization: Bearer <API_KEY>
```

Requests also require the following headers:

```text
Connect-Protocol-Version: 1
Content-Type: application/json
```

A typical request looks like this:

```text
curl https://edge.sterndesk.com/rpc/<service>/<operation> \
  --header "Authorization: Bearer $STERNDESK_API_KEY" \
  --header "Connect-Protocol-Version: 1" \
  --header "Content-Type: application/json" \
  --data '<JSON_BODY>'
```

The exact path and JSON body depend on the operation you are calling.

See the **API Reference** for available operations and their request and response schemas.

## Uploading candidate documents

Uploading candidate documents is different from a standard Sterndesk API request because the upload happens in two steps.

### 1. Create the upload

Call `CreateManualUpload` to create a manual upload.

The operation returns signed, time-limited `params` and `signature` values that are required to upload the files.

Your API key must include the following permission:

```text
sterndesk:documents:write
```

### 2. Upload the files

Send the candidate documents to Transloadit using the `params` and `signature` returned by `CreateManualUpload`.

This request is sent directly to Transloadit rather than to the Sterndesk API, so it does not require your Sterndesk API key.

> **Important:** Send the `params` and `signature` values exactly as they were returned by `CreateManualUpload`. Re-serializing the JSON can invalidate the signature.

See **Upload the files of a manual upload** in the API Reference for the complete request specification.
